# PR Summarizer

PR URL または番号を優先し、なければ現在のブランチの PR を解決する。Issue は対象外。`gh auth status` が失敗した場合は認証を案内して止める。

`gh pr view`（本文、files、commits、checks）と `gh pr diff` を読んだうえで、会話・レビュースレッド・リンク済み Issue は [github-thread-fetcher](../github-thread-fetcher/SKILL.md) の手順で収集する。そこで除外された bot 通知や解決済みスレッドを、未対応事項として復活させない。

## まとめ方

依頼に応じて情報量を変える。

- **短い状況共有**: 目的、主要変更、CI と未解決スレッドだけを数段落で示す。
- **レビュー用**: 目的、変更、変更箇所ごとの確認点、未解決事項、CI を示す。
- **PR 説明文**: PR 本文の事実を整え、変更・検証・関連 Issue を示す。リモートの PR 本文はユーザーの明示依頼なしに変更しない。

影響範囲はパスの接頭辞ではなく、diff が変更する責務から書く。`src/` を一律 frontend とせず、各リポジトリの構成と実装を確認する。分類に確信がないときはファイル名と不確実さをそのまま示す。

## 出力

見出しを固定せず、得られた情報に合わせて以下から必要なものだけを出す。

```markdown
## <PR title>

目的と変更の要約

### 変更
- <利用者または運用への影響を伴う変更>

### 確認ポイント
- <diff から判断が必要な箇所>

### 未対応事項
- `<path>:<line>` <author>: <要求内容>

### CI
- <失敗・実行中・未実行の check。すべて成功ならその事実>
```

本文に根拠がない背景や、diff に現れないテスト結果を推測で補わない。diff が大きい場合は、重要な変更を優先して省略範囲を明記する。
